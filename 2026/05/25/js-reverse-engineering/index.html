反调试绕过案例一：

测试网站 https://www.aqistudy.cn/

目的：绕过网站的反调试手段

网站的现有能检查到的反调试有以下三种：

禁用右键，禁用F2，无限debugger



前面两种尝试全局搜索（ctrl+shift+F）关键词，未找到匹配项，在我多点击几个页面之后，检索关键词并爆出函数”endebug”，继续寻找引用文件，全局搜索或者直接查看对关键词的引用，对此采用文件替换尝试绕过(在抓的包中html路径下的php文件里有一个eval …加密的一行代码，在控制台输出发现也是一处反调试，文件替换注释掉就行)，可以正常进行F12或者右键进行调试了


:::info
搜索关键词没有，无外乎几种情况

其一，管理员对汉字或者关键词做了编码处理，在代码中显示的是其他的字符，再在网页输出中再转换
其二，关键词并没有在代码中出现，而是隐藏在某个文件中的被引用的文件里，网页一般并不会被加载
解决办法：
针对第一种，就是将文字编码之后再搜索，第二种可以多打开几个页面让浏览器多加载几个文件

:::

请求数据解密案例一：

测试网站 https://login.zhangin.com/

目的：寻找网站对于输入账号和密码的加密逻辑

关键字：”param:”

通过关键字，寻找调用堆栈文件对应，数据加密后下断点，可追踪到加密函数za

za(c.value,S)=>加密结果O

S = A + “<><>” + m + “<><>” + w

A=账号

m=密码

w=验证码（无验证码则为空）

这个网站初始登录无需验证码，当后续出现错误登录不正确则会添加验证码进行验证

继续寻找za函数的加密逻辑

（图中，t，r值由e通过如图方法赋值，加密方式则为AES）

AES加密

偏移量 r=za的第一个参数值(r的值由e传输) 54oQDepNSHj4zCuP

模式 CBC

填充 ZeroPadding

密钥 t=za的第一个参数值(t的值由e传输) 54oQDepNSHj4zCuP

在断点处可知，za(c.value, S)，所以具体值为c.value

尝试复现

与浏览器输出结果一致，逻辑正确

后续进行测试，可抓包

“账号<><>密码<><>验证码“

对账号或者密码替换利用此逻辑进行暴力破解

请求数据解密案例二：

测试网站https://auth.xincheng.com/

目的：寻找网站对于输入账号和密码的加密逻辑

方式：单个使用扣代码调用

:::info
针对那种独立的，处理加密运行和其他文件关联较少的文件使用这种方式比较好，因为这种方式是将整个加密逻辑存储到本地运行整个加密流程，若是文件引用其他文件较多，那么需要在本地搭建的加密的环境是比较繁琐的，而且可能因为某一文件引用不到更加容易运行失败出错

:::

关键字：”hidetxtPassword”

寻找到核心的加密逻辑

var encrypt = new JSEncrypt();

encrypt.setPublicKey($("#Public_key").val());

hidetxtPassword = encrypt.encrypt($("#txtPassword").val());

:::info
var encrypt = new JSEncrypt();

创建一个 JSEncrypt 对象。

这个对象用于执行加密、解密、公钥/私钥设置等操作。

encrypt.setPublicKey($(“#Public_key”).val());

$("#Public_key")：使用 jQuery 语法选择页面上 id 为 Public_key 的元素。

.val()：取出该元素的值（一般是 RSA 公钥字符串）。

encrypt.setPublicKey(...)：将这个字符串设置为加密器的 公钥。

encrypt：“加密时要使用这个公钥。”

hidetxtPassword = encrypt.encrypt($(“#txtPassword”).val());

$("#txtPassword").val() 取出输入框（id 为 txtPassword）中的用户密码。

encrypt.encrypt(...) 使用之前设置的公钥对该密码执行加密。

加密后的字符串被保存到变量 hidetxtPassword

:::

调用JSEncrypt对象来源于文件jsencrypt.min.js

查看文件jsencrypt.min.js，没有找到具体的加密逻辑

所以想本地引用此js文件，进行本地复现出算法的加密逻辑

返回数据解密案例：

测试网站:https://www.weibotop.cn/2.0/

目的：将抓包的加密数据进行还原

关键字：currntitems（网站数据包的请求路径名称）

搜索文件路径，爆出main.js文件，寻找到加密逻辑和解密逻辑，尝试断点，发现加密数据解密过程

AES解密

o：需要解密的字符串（断点后可知，t是base64处理后的加密值，t值给i后， n.enc.Base64.parse()是base64的解码方法，o = n.enc.Base64.parse(i)将原来i的值base64解码赋值给o）

r：密钥key（r的值由a赋予）

对字符串进行utf-8的转换，再进行SHA1的哈希计算加密，再将结果进行16字符的转换（s.toString(n.enc.Hex)），并截取前32位字符，最后再将十六进制字符串解析回字节数组

iv：无

模式：ECB

padding：Pkcs7

JSON.parse(e)就是解密结果（控制台可以输出查看）

因为key的值不是固定的，每一次生成都不一样，所以对于数据的加密后的结果，每一次也会不同

想要对于加密的数据进行解密，就需要将源代码扣下来（多个使用替代库模拟）

sign（签名）认证逻辑案例一：

测试网站：yakit靶场（前端验证签名表单HMAC-SHA256）

对于这种登录测试，一般首先采用爆破，但是抓包后对原始包的数据进行修改时，出现了“签名验证失败”，所以采用常规的密码爆破肯定不行的，需要先对签名认证逻辑进行分析，再结合爆破，对账号密码进行破解

在网站进行抓包，找到签名的生成逻辑的调用堆栈，再进行断点查看签名的生成（这里采用的是XHR/提取断点，访问地址时进行断点）

经上分析，在let submitResult = JSON.stringify(outputObj(jsonData), null, 2)后首次出现签名，=

outputObj() 首先调用 outputObj函数，传入 jsonData作为参数

JSON.stringify() 将JavaScript值转换为JSON字符串,里面有三个参数，第一个是outputObj(jsonData)的返回值，第二个null表示不进行替换，第三个2指的是缩进空格数，只是起到格式美化作用

所以判断outputObj(jsonData)函数为sign生成函数，查看调用

signature的值是加密Encrypt(word)后，word值是username=${jsonData.username}&password=${jsonData.password}

再看Encrypt()的加密逻辑

加密采用CryptoJS 库中的 HMAC-SHA256 加密函数，第一个参数“word”为要加密的数据，第二个参数“key.toString(CryptoJS.enc.Utf8)”加密密钥，转换为 UTF-8 字符串格式，最后.toString()：将加密结果转换为字符串格式

key：

var key = CryptoJS.enc.Utf8.parse(‘1234567890123456’);

console.log(key.toString());

是将“1234567890123456”字符串转成ASCII码值，再将数字（并非字符串）ASCII码转换成16进制拼接起来（保持质疑，这点我也不太清楚了，需要仔细再研究）


经验证，与原先网页生成的签名一致，逻辑成功

sign（签名）认证逻辑案例二：

测试网站：https://www.zaixiankaoshi.com/

f12页面查看请求数据包可以看见名为“client”包的负载里面加载sign签名的响应值

寻找sign生成，直接搜关键字不太可行，因为它是伴随着网页数据包的加载产生的，并不是由我们请求生成的sign，当然查看了调用堆栈后发现也不太可行，所以尝试在访问地址进行下断

所以将请求地址断点设置为“client”，当访问此路径时进行断点

sign产生断点成功，对sign生成进行推测，代码从后往前推，也可以看调用堆栈

因为此时的sign值在数据包中由y给予的，再往上追溯，发现y被赋值为 t.data的值,同样发现m是t.header，当然这里不这么重要，所以sign的值可能是被赋予给了t


查看t有没有调用发现并没有什么有用的，所以从调用堆栈的最底部入手，从下往上看，查看t是什么时候产生的，当进入文件查看t的值发现，t已经被赋予了值，当然包含了sign，所以sign肯定是从这个最底部的文件产生的，这时候在当前文件下搜索关键字“sign“，翻了上下所有，发现最相关的一条，t的sign值由来是h产生，所以在附近上下寻找h的产生


找到了

h = Ds()(o + c + r + n + o)

现在查看函数Ds()，采用Md5对数据t进行加密，e表示输出格式的方法名

n是时间戳，获取当前时间

o是固定值：”12b6bb84e093532fb72b4d65fec3f00b”

r是地址移除/api后的值，我没找到相关路径，但是可以直接在函数调用的时候看到，值是：”/banner/get”

c是获取名为“uu”的cookie值，暂定是”af1dfc86-f9be-4220-88eb-1d71ad670859”

将加密逻辑提交给ai，并用node代码写出完整的加密逻辑，或者，配合网站原来发送数据包的形式，结合加密逻辑可以尝试让ai写一份关于加密逻辑的验证
